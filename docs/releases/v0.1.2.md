# humane-kotlin v0.1.2

## `Humane.humanSize` now matches Finder at every size

Earlier versions rounded every size to 3 significant figures. That matched
every test fixture at the time, but real Finder output showed it was wrong
for most sizes under 10 MB and above 100 MB. Sizes now use Finder's fixed
decimal places per unit -- KB 0, MB 1, GB and above 2 -- rounded half up,
with trailing zeros trimmed. When rounding reaches 1000 of a unit, the size
moves up to the next unit instead.

```kotlin
Humane.humanSize(4_132_383)   // "4.1 MB"   (was "4.13 MB")
Humane.humanSize(123_456_789) // "123.5 MB" (was "123 MB")
Humane.humanSize(2_579)       // "3 KB"     (was "2.58 KB")
Humane.humanSize(999_999)     // "1 MB"     (was "1000 KB")
```

Every expected value was checked against real Finder output (see
[humane#3](https://github.com/woodie/humane/issues/3)), and the spec suite
gains 14 new cases covering each unit and the round-up boundaries.
